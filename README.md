# gemma-4-developer-agent

Code, runs and paper for the [Gemma 4 Developer Agent](https://www.kaggle.com/competitions/gemma-4-developer-agent)
Kaggle competition and its paper track. Given a real GitHub issue on fastapi, rich, requests or
httpx, an agent edits the repository offline and submits a patch, scored SWE-bench style: hidden
tests must pass.

A submission is declarative: `agent.yaml`, prompts, sub-agents, skills and optional LoRA adapters,
compiled by the organisers' harness into a Google ADK agent that runs one Gemma 4 model (31B, 12B,
E4B or E2B, int4) served by vLLM on 4x L4, with a 32k context and 12 hours for the hidden test set.

## The paper: prompt recipes for a 4B agent

*Prompt Recipes Do Not Help a 4B Coding Agent, Even When It Follows Them: A Pre-registered Factorial
Screening* ([draft](docs/paper/draft_screening.md)). Eight prompt recipes for Gemma 4 E4B, screened
in a 2^(8-3) fractional factorial design: 32 configurations, 72 tasks, 2,304 attempts.

- Pre-registration, frozen before the main run, with the SHA-256 of every file it pins:
  [`docs/paper/preregistration_screening.md`](docs/paper/preregistration_screening.md).
- The 32 configurations: `variants/screening/s00` to `s31`, generated by
  `scripts/make_screening.py`; the design matrix is `variants/screening/design.json`.
- Exact run files of the three Kaggle kernels: `reports/runs/screening-sc{1,2,3}/run.py`; run log:
  `reports/ledger.jsonl`.
- One record per attempt, without task text: `docs/paper/records/screening_attempts.csv`.
- Analysis: `docs/paper/analysis/screening/` (`analyze.py` is the frozen primary analysis,
  `explore.py` the exploratory numbers, `figures.py` the figures).

### Reproduce every number on CPU

```bash
python3 -I docs/paper/analysis/screening/reproduce.py             # pre-registered analysis
python3 -I docs/paper/analysis/screening/reproduce.py --explore   # exploratory numbers
```

`reproduce.py` feeds the published records to the frozen scripts, unchanged, and matches the output
of the analysis run on the agent traces. Python 3.12+ standard library only.

### Rerun the experiment

It needs the competition data (not redistributed here) and a Kaggle account with GPU quota.

```bash
kaggle competitions download -c gemma-4-developer-agent -p data && unzip -oq data/*.zip -d data
uv sync && uv run pytest
uv run python scripts/make_screening.py            # the 32 configurations
uv run python scripts/make_eval_kernel.py --variant s00=variants/screening/s00 ... \
    --tasks reports/screening_block1.txt --concurrency 8 --shuffle-seed 20261101 --slug <slug>
kaggle kernels push -p submissions/<slug>
```

`scripts/make_eval_kernel.py --mode noop` runs the control in which the patch changes nothing.

## The agent

- `agent/`: the submission source.
- `src/g4agent/package.py`: validation with the harness's own checks, and packaging into
  `submissions/submission.zip` (`scripts/build_submission.py`).
- `scripts/fetch_harness.sh`: fetches the official harness wheels from the competition's
  wheelhouse dataset into `vendor/`.
- `kaggle/runner.py` and `cloud/modal_eval.py`: run the official harness on Kaggle or Modal GPUs.
- `docs/paper/` also keeps the earlier research notes (`literature.md`, `gaps.md`,
  `proposals.md`) and the first pre-registration (`preregistration.md`).
